# ADR 0005: PDF rendering decisions

- Status: Accepted
- Date: 2026-11-20
- Source: code comments removed in the comment cleanup

## PDF carousel clones leave a canvas blank rather than substitute another page

**Context.** Copying a page canvas can throw when it is protected (tainted) or detached.

**Decision.** Catch the drawImage error and leave the cloned canvas blank; never fill it with another page.

**Consequences.** A failed clone shows an empty page instead of wrong content.

**Code.** `app/hooks/pdf-page-carousel.ts#cloneCanvas`

## PDF selection detection uses pointerup only

**Context.** Touch and pen produce synthesized mouse events after pointer events, which would fire selection handling twice.

**Decision.** Listen to pointerup (primary button only) for mouse, pen, and touch, not mouseup.

**Consequences.** One selection popover per gesture on every input type.

**Code.** `app/hooks/use-pdf-highlights.ts#handlePointerUp`

## PDF highlights reuse cfiRange with a synthetic page/offset key

**Context.** Highlights are stored with a cfiRange key designed for EPUB, but PDFs have no CFIs.

**Decision.** PDF highlights use cfiRange = "pdf:page:<page>:offset:<textOffset>:len:<length>", where the offset is a character offset into the page text layer.

**Consequences.** PDF and EPUB highlights share one store and schema; anything parsing cfiRange must handle the pdf: prefix (applyTempHighlight parses it with a regex).

**Code.** `app/hooks/use-pdf-highlights.ts#makePdfCfiRange`

## Right-click on a PDF highlight does not start a text selection

**Context.** A right-click or ctrl-click on a highlight mark would otherwise start a text selection in the text layer and open the selection popover.

**Decision.** preventDefault on mousedown for button 2 or ctrl+button 0 on highlight marks.

**Consequences.** The context menu opens cleanly without a stray selection.

**Code.** `app/hooks/use-pdf-highlights.ts#renderHighlightOverlay`

## PDF arrow-key navigation listens on the whole document

**Context.** Users should not have to click the PDF viewer or nav buttons before arrow keys work.

**Decision.** handleKeyDown is attached to document with no focus check. It is skipped in continuous scroll mode and while typing in an editable element; in workspace focused mode it only responds when this book is the active cluster.

**Consequences.** Arrow keys always turn pages for the visible PDF; several open PDFs rely on activeClusterBookIdRef to avoid all turning at once.

**Code.** `app/hooks/use-pdf-lifecycle.ts#handleKeyDown`

## PDF outline extraction failures are non-fatal

**Context.** Many PDFs have broken or missing outlines.

**Decision.** Catch getOutline errors and keep the reader open with an empty TOC.

**Consequences.** The book still opens; the TOC is just empty.

**Code.** `app/hooks/use-pdf-lifecycle.ts#init`

## PDF scale is applied after pagesinit

**Context.** Named scale values (page-width, page-fit) need page sizes, which are only known once the first page is ready.

**Decision.** Apply layout scale and restore position inside the pagesinit handler.

**Consequences.** Scale is correct on open; work done earlier would use wrong page dimensions.

**Code.** `app/hooks/use-pdf-lifecycle.ts#init`

## PDF layouts map to raw pdf.js ScrollMode and SpreadMode numbers

**Context.** pdf.js exposes ScrollMode (VERTICAL=0, PAGE=3) and SpreadMode (NONE=0, ODD=1, EVEN=2) as enums, but the code uses literal numbers.

**Decision.** continuous uses ScrollMode.VERTICAL (0); two-page uses ScrollMode.PAGE (3) with SpreadMode.EVEN (2); every other layout uses ScrollMode.PAGE (3) single-page with SpreadMode.NONE (0).

**Consequences.** The numbers must stay in sync with pdf.js; importing the enums would make this self-describing.

**Code.** `app/hooks/use-pdf-lifecycle.ts#layoutToScrollMode`

## PDF chat context reuses the loaded pdf.js document

**Context.** Building a new pdf.js document for each page turn just to extract text is slow.

**Decision.** Extract page text from pdfDocRef when it exists; load raw book data and create a document only as a fallback when no pdfDocRef is passed.

**Consequences.** Chat context updates cheaply on page turns.

**Code.** `app/hooks/use-pdf-workspace-panels.ts#usePdfWorkspacePanels`

## Load the pdfjs worker via a Vite URL import

**Context.** pdfjs needs GlobalWorkerOptions.workerSrc set to a worker script URL.

**Decision.** Resolve the bundled worker with new URL('pdfjs-dist/build/pdf.worker.min.mjs', import.meta.url) so Vite handles it as an asset.

**Consequences.** Worker is fingerprinted and served by the build; setup is lazy and done once per module.

**Code.** `app/lib/pdf/pdf-service.ts#ensurePdfWorker`

## Copy PDF bytes before passing them to pdfjs

**Context.** pdfjs.getDocument({data}) transfers/detaches the ArrayBuffer it receives, which breaks callers that reuse the buffer.

**Decision.** Always pass a copy (new Uint8Array(data).slice()) to getDocument.

**Consequences.** Extra memory per load, but callers keep a usable buffer. Applies in pdf-service.ts and pdf-text-extract.ts.

**Code.** `app/lib/pdf/pdf-service.ts#parsePdf`, `app/lib/pdf/pdf-text-extract.ts#extractPdfChapters`

## PDF chapter extraction returns partial results on failure

**Context.** Worker init, getDocument, or individual pages can fail mid-extraction.

**Decision.** extractPdfChapters catches errors, logs a warning, and returns the pages extracted so far instead of throwing.

**Consequences.** Callers may receive fewer chapters than pages; no error surfaces to the UI.

**Code.** `app/lib/pdf/pdf-text-extract.ts#extractPdfChapters`

## Migrate legacy pdfLayout 'fit' to 'fit-height'

**Context.** The pdfLayout enum used to include 'fit', which was renamed.

**Decision.** readLocalUI rewrites a stored 'fit' value to 'fit-height' before decoding.

**Consequences.** Old local settings decode without falling back to defaults.

**Code.** `app/lib/settings.ts#readLocalUI`
