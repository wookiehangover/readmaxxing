# ADR 0003: Authentication decisions

- Status: Accepted
- Date: 2026-11-20
- Source: code comments removed in the comment cleanup

## Reset local data logs out server-side but never blocks on it

**Context.** The session cookie is HttpOnly and cannot be cleared client-side, but a logout failure must not prevent a local reset.

**Decision.** DataSection reset calls logout() to clear the HttpOnly session cookie server-side and ignores any error.

**Consequences.** The local reset always completes; a failed logout may leave a server session.

**Code.** `app/components/settings/data-section.tsx#DataSection`

## WebAuthn RP ID must match the serving domain

**Context.** WebAuthn rejects ceremonies when the relying party ID is not the domain (or a registrable suffix) the page is served from.

**Decision.** WEBAUTHN_RP_ID is a required env var set per deployment to the app domain.

**Consequences.** Each environment needs its own RP ID; passkeys do not move between domains.

**Code.** `app/lib/auth-config.ts#getRpId`

## CLI login callback accepts only the CLI loopback address and path

**Context.** The browser login hands a token to a callback URL from the query string; an arbitrary URL would let an attacker steal the session.

**Decision.** parseCliCallback accepts only the loopback address and path the CLI generates, plus a 43-character base64url state, and rejects everything else.

**Consequences.** Open-redirect and token exfiltration through the callback are blocked; CLI changes to the callback shape must update this check.

**Code.** `app/lib/cli-login-callback.ts#parseCliCallback`

## Demo content adoption is best-effort after sign-in

**Context.** After sign-in or registration, the auth saga tries to adopt local onboarding demo content into the account.

**Decision.** Errors from demo content adoption are caught and logged as a warning; authSessionResolved is still dispatched because the server already confirmed the session.

**Consequences.** Users always finish signing in; demo content may be missing from the account if adoption fails.

**Code.** `app/lib/themis/auth-session/auth-session-sagas.ts`

## CLI sessions are separate and revocable

**Context.** The CLI needs its own credential after the user approves in a browser.

**Decision.** Issue a distinct session row for the CLI rather than reusing the browser session, only after explicit browser approval.

**Consequences.** CLI access can be revoked independently of browser sessions.

**Code.** `app/routes/api.auth.cli.ts#action`

## Require same-origin for CLI session issuance

**Context.** POST /api/auth/cli returns a new session credential for the CLI.

**Decision.** Reject requests whose Origin header does not equal the request origin, in addition to requiring auth.

**Consequences.** Cross-site pages cannot mint CLI credentials via the user cookie (CSRF); non-browser callers must send a matching Origin.

**Code.** `app/routes/api.auth.cli.ts#action`

## Discoverable passkeys with required user verification

**Context.** Login starts without knowing the user; verifyAuthenticationResponse requires user verification.

**Decision.** generateAuthenticationOptions uses an empty allowCredentials (discoverable credentials) and userVerification "required" to match the verify step.

**Consequences.** Authenticators must support resident keys and UV; options and verification policy must stay in sync.

**Code.** `app/routes/api.auth.login-options.ts#loader`

## Persist passkey signature counter after login

**Context.** WebAuthn signature counters detect cloned authenticators/replay.

**Decision.** After successful verification, store authenticationInfo.newCounter on the passkey (then touch last-used).

**Consequences.** Counter regressions are rejected by verification on later logins.

**Code.** `app/routes/api.auth.login-verify.ts#action`

## WebAuthn challenges are single-use and deleted before verification

**Context.** A challenge must never be replayable.

**Decision.** Delete the challenge row immediately after lookup, before verifying the response, in both login-verify and register-verify.

**Consequences.** A failed verification consumes the challenge; the client must start a new ceremony to retry.

**Code.** `app/routes/api.auth.login-verify.ts#action`

## Logout re-parses the session cookie for the raw session id

**Context.** getSessionFromRequest returns only { userId }, but deleting a session requires its id.

**Decision.** Logout re-reads the readmax_session cookie from the Cookie header to get the session id and deletes that row.

**Consequences.** Cookie name/parsing is duplicated in logout; if the helper ever exposes the id this can be simplified.

**Code.** `app/routes/api.auth.logout.ts#action`

## Each registration ceremony creates a new anonymous user

**Context.** Accounts are passkey-only with no username.

**Decision.** register-options upserts a fresh user with a random UUID for every registration ceremony.

**Consequences.** Abandoned ceremonies may leave orphan users; existing-passkey exclusion is effectively empty for new users.

**Code.** `app/routes/api.auth.register-options.ts#loader`

## CLI approval falls back to manual credential display

**Context.** The browser posts the credential to a localhost callback which may be unreachable.

**Decision.** On callback failure, swallow the error and show the same credential for manual entry.

**Consequences.** Users can always complete CLI login.

**Code.** `app/routes/cli.tsx#CliRoute`

## CLI never sends a saved token to an overridden server URL

**Context.** A saved session belongs to a specific server URL; users can pass --url to target another server.

**Decision.** The saved token is used only when saved.url equals the target URL; READMAXXING_TOKEN env still applies.

**Consequences.** Prevents leaking credentials to arbitrary servers; users must log in per server.

**Code.** `packages/cli/src/config.ts`

## CLI login callback is single-use and loopback-only

**Context.** The CLI receives the session token from the browser through a local HTTP callback.

**Decision.** startLoginCallback accepts exactly one login attempt on the loopback interface. After reading the body it rechecks closed/connected/pending and returns 409 because two callbacks can arrive concurrently. Once the session is saved it settles "connected" even if the browser response was destroyed/timed out.

**Consequences.** A browser timeout cannot strand a CLI whose session was already saved; concurrent callbacks cannot double-connect.

**Code.** `packages/cli/src/login-callback.ts#startLoginCallback`

## CLI login also accepts a pasted token via hidden input

**Context.** The browser may be unable to reach the terminal's loopback callback (remote shells, firewalls).

**Decision.** Login keeps a muted stdin prompt available alongside the callback so the user can paste a token.

**Consequences.** Works in remote/SSH sessions.

**Code.** `packages/cli/src/login.ts`

## CLI logout only clears the saved session if it matches the active credential

**Context.** An environment token (READMAXXING_TOKEN) can differ from the saved session.

**Decision.** Logout deletes the saved config only when its url and token match the credential that was logged out.

**Consequences.** Logging out an env credential does not wipe an unrelated saved session.

**Code.** `packages/cli/src/main.ts`
